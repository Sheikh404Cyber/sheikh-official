# Sheikh-OFFICIAL — Amin Sheikh's personal platform

**Editorial redesign (2026-11-05):** the homepage was rebuilt to a dark
editorial design system reverse-engineered from a reference portfolio
(assembly-on-scroll motion grammar, Anton/Caveat display type, numbered
sections, giant accent word band, triptych hero portrait, red accent
`#e10600`). Motion runs on a CSS reveal layer plus a self-hosted
GSAP/ScrollTrigger/SplitText/Lenis layer. See `REFERENCE_ANALYSIS.md`,
`DESIGN_SYSTEM.md`, `ANIMATION_GUIDE.md`, `TECH_STACK.md`, `QA_REPORT.md`.

Public showcase (tools, tutorial videos, website demos) + member accounts
with admin-granted download permission + a full admin panel (users, tools,
videos, websites, settings). Built like The Wildcut: **Cloudflare Pages +
Pages Functions + D1**, no build step, plain HTML/CSS/JS.

**v2 (2026-11-01):** paid tools (price + demo video per tool, WhatsApp Buy
buttons, Bkash/Nagad "How to Buy" section), per-tool ownership grants
(`user_tools`) + a `/my-tools` library page, a 3-photo hero strip managed
in the new admin **Photos** tab (URL or direct upload into D1
`media_blobs`, served by `/api/media/:key`), buyer **Reviews** and **FAQ**
sections (admin CRUD), and a **Hire Me** order form feeding the admin
**Orders** tab. The public header no longer shows an Admin link — the
owner opens `/admin` directly. **Deploying v2 to the live site only needs
`migrations/0003_v2.sql` applied to the remote D1** (plus the usual Pages
deploy); settings defaults (WhatsApp `8801957566098`, `/media/photo-N.jpg`)
are handled in code, and the sales numbers are edited in Admin → Settings.

## How it works

- **Passwords:** PBKDF2-HMAC-SHA256, 100k iterations, per-user salt. Never stored/logged in plain text.
- **Sessions:** random 256-bit token; only its SHA-256 hash is stored. Cookie
  `so_session` — HttpOnly, Secure, SameSite=Lax, 30 days. Blocking a user or
  changing a password kills that user's sessions.
- **Downloads:** visitors see tools locked with a WhatsApp Buy button. A
  user **owns** a tool when they are the admin, have `can_download = 1`
  (all tools, Users tab switch), or hold a per-tool grant in `user_tools`
  (Users tab → "Tools access" — the normal flow after a purchase). Owners
  get a real Download button → `GET /api/tools/:id/download` (302 to the
  on-site file or the external link, e.g. a GitHub release for the ~95 MB
  QuickVid) and the download is logged. Owned tools are collected on
  `/my-tools`. Mutating API calls require a same-origin Origin header.
- **Sales settings:** WhatsApp/Bkash/Nagad numbers and the three hero
  photo URLs live in `settings` (Admin → Settings / Photos). They are
  published to buyers only through `GET /api/site-config`, which returns
  exactly those keys — never `setup_token_hash` or anything else.
- **Admin:** every `/api/admin/*` route is behind the `is_admin` session
  guard. The admin cannot block/delete their own account.
- **One-time admin setup link:** only the SHA-256 hash of a random token is
  stored (`settings.setup_token_hash`). Opening `/setup?token=<raw>` lets
  the owner set the admin password once: the token is then deleted, the
  admin's old sessions are killed, and the seeded temp password stops
  working. 10 wrong-token attempts burn the token as well.

## Local development

```sh
# 1) Handler tests (mock D1 backed by a real SQLite db built from schema.sql)
node tests/test-handlers.mjs

# 2) SQL lint — every SQL string in functions/ EXPLAINed against schema.sql
python3 ../wildcut/check-sql.py .

# 3) Full local stack with wrangler (optional)
npx wrangler pages dev public --d1 DB=<local-db-id>
#    then apply schema.sql + seed.sql to the local D1 (wrangler d1 execute --local)
```

Pages routing notes: `public/login.html` serves `/login`, `public/signup.html`
serves `/signup`, `public/setup.html` serves `/setup`, `public/admin/index.html`
serves `/admin`.

## Deploy (parent does this)

1. Create the D1 database; put its id into `wrangler.toml`
   (`database_id = "PLACEHOLDER-filled-at-deploy"`).
2. `node scripts/seed.mjs` — (re)generates `seed.sql` + `ADMIN-TEMP.txt`.
3. Apply schema + seed:
   `wrangler d1 execute sheikh-official-db --file=schema.sql` and `--file=seed.sql`
   (or paste them in the D1 console).
4. Connect the repo to Cloudflare Pages (framework preset: **None**, build
   output dir `public`) — or `wrangler pages deploy public`.
5. **One-time admin setup link (preferred — no password travels through
   chat):** generate a random token, store only its SHA-256 hash, and give
   the owner the link exactly once:
   ```sql
   INSERT OR REPLACE INTO settings (key, value)
   VALUES ('setup_token_hash', '<sha256-hex-of-the-raw-token>');
   ```
   Owner opens `https://<site>/setup?token=<rawToken>` and sets his own
   admin password. The link is **single use**: on success the hash row is
   deleted, the seeded temp password dies, and the admin's sessions are
   reset (10 wrong-token attempts burn the link too). Fallback if the link
   is lost before use: log in at `/login` with the ADMIN-TEMP.txt password,
   change it in **Admin → Settings**, then delete `ADMIN-TEMP.txt` and
   rotate/remove the generated `seed.sql` from the repo history if it was
   committed.
6. Replace the QuickVid tool's placeholder external URL with the exact
   GitHub release asset URL (Admin → Tools → SHEIKH QuickVid → Edit), or via
   the seeded `tools.external_url`.
